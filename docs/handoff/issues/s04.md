## Goal
Build the lobby's HUD in the Toy style, exactly as the UI track drew it. The lobby HUD and panel exist (#142, `lobby_hud.gd`, `lobby_panel.gd`): this issue reworks their look and drops today's key prompt.

## Build
The scene tree, node for node, is in prime-game-ui [`docs/handoff/s04-lobby.md`](https://github.com/xperiaroco2/prime-game-ui/blob/ui-0.2.0/docs/handoff/s04-lobby.md) at the tag `ui-0.2.0`. The states are drawn on the review page https://claude.ai/artifact/SCREENS_URL (screen s4; uk and en, default and large text).

- `Plates` (CanvasLayer 1): the name plate layer, the same as the round's (ISSUE_S7). Built once.
- On the HUD layer (CanvasLayer 2): `Cross` (the crosshair), `Status` (ToyPlate, top centre), `Players` (a 400 px ToyPlate, top right: the lobby name and the code row, then the count and the rows), `Bottom` (bottom left: the own ready chip and the mic). Edges 40 px in.
- States: `wait`, `count`, `short`, `code-waiting`, `direct`.

Rules:
- Theme type variations from the `ui-0.2.0` pack only (#288). No `add_theme_*_override` and no `theme_override_*` (`theme_test.gd`): gaps come from the spacing variations (`ToyColumn…`, `ToyRow…`), and a gap the scale lacks is the empty `Control` spacer the handoff gives.
- Every player-facing text is a deck key through `tr()` (`tr_n()` for `lobby.need_more`). A key with placeholders is set from code with `auto_translate_mode = DISABLED` and rebuilt on `NOTIFICATION_TRANSLATION_CHANGED` (#208). Data texts (player and lobby names, the code) are set from code with `auto_translate_mode = DISABLED`.
- Sizes and offsets are px at the 1920×1080 base (#287). A size from a variation's size constants is read with `get_theme_constant()` into `custom_minimum_size`, as the node lines give it.
- Icons are the pack's white SVGs, tinted as each node line says, imported at the `svg/scale` the handoff's notes give.

## Behaviour
- The mouse is captured in the lobby; every node has `mouse_filter = IGNORE`. No control takes focus.
- Ready toggles on the bound ready key (`control.ready`, F, rebindable in Settings › Controls, #211). No prompt on screen; the Esc menu's Lobby tab has the Ready button.
- Status: `lobby.waiting` ({count} ready of {total} players). `lobby.need_more` (`tr_n`) while the lobby has fewer players than the mode needs; other unmet demands take their own keys later (#208). During the countdown, `lobby.countdown` in ToyTitleOnDark, once a second from 5 to 1. The countdown starts when everyone is ready and the mode's demands are met; an un-ready stops it.
- Players: the lobby name the host set (#214), or `lobby.default_name` with the host's name while it is the default. The code row shows to the host and to every player who joined with the code (M6 §3), hidden for a Direct joiner; the code reads `…` while the code service has not made the room (CODE_WAITING) and `—` when the service is gone. Copy lives in the Esc Lobby tab. Then `lobby.player_count` and one row per player in join order, the host first: the host's row reads `lobby.host_mark` with the name, the own row `player.you`, others the name alone. Names are cut with an ellipsis. A ready player shows the check; a not-ready player shows no mark. The plate is rebuilt when a player joins, leaves, renames or toggles ready.
- Bottom: the own ready chip (ToyChipPlate `lobby.ready_no` while not ready, ToyChipLight `lobby.ready_yes` while ready) and the mic: `mic.svg` in `icon_on` while anybody can hear the player, `mic-off.svg` in `icon_off` when nobody does.
- Name plates (#257): one per other player in line of sight within about 10 m. `position = camera.unproject_position(head + 0.35 m)`, the plate centred on it; hidden behind walls (raycast), beyond 10 m or behind the camera. No role, no health; no teammate mark in the lobby.
