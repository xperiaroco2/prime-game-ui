## Goal
Build the connecting, failure and loading screens in the Toy style, exactly as the UI track drew them. The join steps and failures exist (#373, PR #430), as do the shell's connecting and loading screens (#142, `connecting_screen.gd`, `loading_screen.gd`): this issue reworks their look.

## Build
The scene tree, node for node, is in prime-game-ui [`docs/handoff/s03-connecting.md`](https://github.com/xperiaroco2/prime-game-ui/blob/ui-0.2.0/docs/handoff/s03-connecting.md) at the tag `ui-0.2.0`. The states are drawn on the review page https://claude.ai/artifact/SCREENS_URL (screen s3; uk and en, default and large text).

- One screen on the black-screen layer (CanvasLayer 6): `Night` (ToyBackdropNight, opaque, `mouse_filter = STOP`).
- `Connecting`: a 768 px column with the spinner, the title and the step, the code row, the elapsed time and Cancel.
- `Failure`: one 848 px layout for every failure: title, body, then the buttons 32 px below.
- Loading: `Loading` (title, bar, players) and `Tip`; or `Head` (title, bar) and `Card`, the how-to card (ToyPanelHowto, raised), which is the shared card scene of ISSUE_S8.
- States: `finding`, `connecting-direct`, `joined`, `fail-no-room`, `fail-started`, `fail-version`, `fail-full`, `fail-service`, `fail-unreachable`, `fail-no-answer`, `lost`, `map-failed`, `error`, `host-failed`, `load`, `load-card`.

Rules:
- Theme type variations from the `ui-0.2.0` pack only (#288). No `add_theme_*_override` and no `theme_override_*` (`theme_test.gd`): gaps come from the spacing variations (`ToyColumn…`, `ToyRow…`, `ToyGridList`, `ToyGridSwatch`; `ToyScroll` for a list's gap to its bar), and a gap the scale lacks is the empty `Control` spacer the handoff gives.
- Raised panels and buttons through `ToyRaised` (placement, size and visibility on the wrapper), presses through `ToyPress` (#289).
- Every player-facing text is a deck key through `tr()`. A key with placeholders is set from code with `auto_translate_mode = DISABLED` and rebuilt on `NOTIFICATION_TRANSLATION_CHANGED` (#208). Data texts (the code, the lobby name the host typed, player names, times) are set from code with `auto_translate_mode = DISABLED`.
- Sizes and offsets are px at the 1920×1080 base (#287). A size from a variation's size constants is read with `get_theme_constant()` into `custom_minimum_size`, as the node lines give it.
- Icons are the pack's white SVGs, tinted as each node line says, imported at the `svg/scale` the handoff's notes give.

## Behaviour
- Connecting shows from Join until the lobby (s4) or a failure. Leaving (left, closed) shows nothing here: straight to the main menu.
- The spinner turns once a second about its centre (`pivot_offset_ratio` 0.5, 0.5); half speed under reduced motion.
- Title: `connect.connecting_unnamed` until the host's lobby name arrives (#214), then `connect.connecting` with `{lobby}`: the host's text, or `lobby.default_name` with the host's name while it is the default.
- Step from `JoinProgress.step()`: FINDING, CONNECTING, JOINED to `connect.step.finding`, `.connecting`, `.joined`. A Direct join starts at CONNECTING.
- A code join shows the code (a keycap) and the time since Join (m:ss, every second). A Direct join shows neither the code row nor any address.
- Cancel is the only button (raised), focused on open; Cancel or Esc aborts the join and returns to the main menu with the code or address kept in its field. The traversal timeout is the game's (M6 §2.3).
- Failures take their texts from the EndReasons id, as the handoff's state table maps them: `no_room`; `joins_closed`; `wrong_version`, `wrong_content`, `service_refused`, `unknown_map` (plus the two version lines from `JoinProgress.found_detail` when known); `full`; `service_unreachable`; `host_unreachable`; `connect_failed`; `host_lost`; `load_failed`, `load_deadline`; `row_error`, `own_client_malformed`, `own_client_disconnected`; `cannot_host`. Join failures share `connect.fail.title`; a session that ended or a host that could not start has its own title.
- Where a failure has an action, Primary takes focus with a flat Back beside it: `connect.fail.retry` tries the same target again (`host-failed`: hosts again the same way), `connect.fail.direct` opens the main menu's Direct panel with the code kept. Otherwise Back stands alone, raised and focused. Esc = Back. Back returns to the main menu with the code or address kept.
- Loading runs from the Loading phase until pre game (s6): this machine's load fraction; one row per player, the host first, then join order (the own row `player.you`; `loading.player_loading` muted while loading, `loading.player_ready` once loaded); one random `tip.*`.
- `load-card`: instead of the players and the tip, the how-to card of a task type in this round that the player has not completed, at most twice per type and never after its first completion (`user://` counters, #254). The card is content data per task type; its frames are wordless, each one art PNG of the pack (Delivery: `dist/pack/cards/delivery-1.png` to `delivery-4.png`). No line says the task is new.
