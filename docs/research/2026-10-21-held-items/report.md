# How games show carried items in the HUD

Research for the engineer's question of 2026-10-21 (chat, translated): "it means we must make an icon for every item;
how do other games do it? LOCKDOWN Protocol has no icons, it just writes the name". Four gatherer agents read the web
(text only); the fandom and several wiki.gg wikis refused the fetches, so the evidence is thin and much is marked
"(unconfirmed)". No developer statement on why a HUD looks as it does was found for any game.

## Making icons without drawing each one

- **Rendered from the 3D model.** A camera renders each item once to a PNG (an orthogonal camera, fixed lights,
  an unshaded or outlined look); after the setup a new item costs almost nothing, and the icon matches the 3D art
  ([Godot forum](https://forum.godotengine.org/t/how-to-create-a-icon-texture-from-a-scene/2656)). In Godot 4: a
  SubViewport with its ViewportTexture, `get_image()` and `save_png()` (slow, so bake once, not every frame)
  ([SubViewport](https://docs.godotengine.org/en/stable/classes/class_subviewport.html),
  [ViewportTexture](https://docs.godotengine.org/en/stable/classes/class_viewporttexture.html)). Addons: SceneTexture
  (MIT, [GitHub](https://github.com/ydeltastar/godot-scene-texture)); Thumbnailer (GPLv3, not on this repo's licence
  list, [asset](https://godotengine.org/asset-library/asset/5101)). Live 3D viewports per slot are costly; bake to PNG.
- **A generic icon plus the name** for most items, drawn icons only for the few tools (Lethal Company).
- **Only the name** (LOCKDOWN Protocol, per the engineer): no art at all; it must be read, not recognised.

## Accessibility

No guideline compares an icon with a name in an inventory. The guidelines say no essential information by colour alone
([GAG](https://gameaccessibilityguidelines.com/ensure-no-essential-information-is-conveyed-by-a-fixed-colour-alone/)),
4.5:1 for important visual elements and pictures that carry information
([XAG 102](https://learn.microsoft.com/en-us/gaming/accessibility/xbox-accessibility-guidelines/102)), and text at least
18 px at 1080p on PC ([XAG 101](https://learn.microsoft.com/en-us/gaming/accessibility/xbox-accessibility-guidelines/101)).
A picture with its name beside it satisfies both readings (agent's inference).

## For this game

| Way | Work per new item | Fits the sticker | Needs |
|---|---|---|---|
| Name only | none | yes (a sticker tag) | nothing |
| Render of the 3D model + name | none after a one-time setup | with an ink outline added in the render | the items' 3D models (art track) and a bake step in the game's tools |
| Drawn pictograms + name | one drawing per item | yes, if drawn in the room signs' language | a drawing per item, forever |
| Generic icon + name, drawn icons for tools only | a few drawings | yes | a rule for what is a "tool" |
| Nothing (item seen in the hand) | none | n/a | a camera that always shows the hand |

The agent's reading, for the engineer to decide: the name now (it costs nothing and he named it), and a render of the
3D model next to it once the art track has the models, since it never needs a drawing per item.
